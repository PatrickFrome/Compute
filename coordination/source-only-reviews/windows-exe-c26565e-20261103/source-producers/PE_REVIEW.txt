Exact transform stages
The pinned builder injects ASAR integrity before user afterPack, then writes
fuses, then edits product resources and optionally signs. A future producer must
derive separate expected images for afterPack and final readback. Comparing an
afterPack candidate against a final-stage recipe is incorrect.
https://github.com/electron-userland/electron-builder/blob/electron-builder%4026.15.7/packages/app-builder-lib/src/platformPackager.ts#L320-L356

ASAR stage: addWinAsarIntegrity pushes a new INTEGRITY/ELECTRONASAR entry; it does
not replace an existing entry. Pre-editing the distribution and letting the
unchanged builder run would introduce duplicates. The payload is independently
computed from all intended staged ASAR header strings, using SHA256 and normalized
Windows paths. readAsarHeader reads the size pickle and header pickle before
returning the string; hashing the complete ASAR file is a different operation.
Use explicit size limits, complete reads, and independently verified staged
inputs. Candidate EXE resources must never supply their own expected hashes.
https://github.com/electron-userland/electron-builder/blob/electron-builder%4026.15.7/packages/app-builder-lib/src/electron/electronWin.ts#L8-L42
https://github.com/electron-userland/electron-builder/blob/electron-builder%4026.15.7/packages/app-builder-lib/src/asar/asar.ts#L149-L171

Fuse stage: the builder resolves nested @electron/fuses 1.8.0; final application
readback uses top-level 2.1.3. For the current config the intended changes are
only source-anchored fuse indices 4 and 5 to 0x31. A small independent fixed-wire
operation can avoid executing the fuses package closure, provided it requires
exactly one unambiguous valid x64 wire, preserves its sentinel/version/length and
all other states, and rejects malformed or duplicate wires. Fuse-only support
cannot admit this pipeline because the earlier ASAR resource edit is mandatory.
https://github.com/electron/fuses/blob/v1.8.0/src/index.ts#L55-L118

Why replay alone is insufficient for the requested preservation proof
pe-library's resource parser permits only the relocation section after resources.
Its resource serializer sorts/rebuilds directory structures, descriptor RVAs and
payload/padding bytes. Resource growth can move the relocation section's raw
offset/RVA and change image size. generate() reconstructs section/header/gap
bytes, removes the certificate directory, and conditionally recalculates the PE
checksum. Therefore whole-image equality with a replay establishes the precise
builder transformation relation, not automatically invariant loader semantics.
https://github.com/jet2jet/pe-library-js/blob/94974834fc131c99963fd1635e5bfbc135b160bd/src/main/NtExecutableResource.ts#L622-L664
https://github.com/jet2jet/pe-library-js/blob/94974834fc131c99963fd1635e5bfbc135b160bd/src/main/NtExecutableResource.ts#L728-L912
https://github.com/jet2jet/pe-library-js/blob/94974834fc131c99963fd1635e5bfbc135b160bd/src/main/NtExecutable.ts#L369-L532

Minimum conservative future profile
Require a valid, ordinary, unsigned PE32+ x64 image with bounded, non-overlapping
headers/raw/virtual ranges, valid alignments, and exactly one read-only,
non-executable, non-writable resource section. Its resource-directory RVA must
start at that section. Reject duplicate/ambiguous names, directories, resources
or wires, unsupported sections and truncated/overflowing layouts.

Require unchanged section count, raw offsets/sizes, virtual addresses, aligned
mapped spans, permissions, entry point, image base, subsystem and DLL flags.
Resource raw capacity must already fit both serialization stages; otherwise
HOLD. The resource virtualSize and resource-directory size may differ only by
the exact replay-calculated values while preserving the aligned mapped span.
Keep all other header bytes identical except the exact mathematically expected
checksum after each serializer stage. Certificate offset and size must stay
zero. No certificate, checksum, header, gap, overlay or section is ignored.

Require exact preservation of every non-resource raw byte, file gap and overlay,
except the validated two fuse states. The producer must compare the entire
expected serialized resource section, not omit .rsrc from identity. Preserve all
unselected resource payloads/metadata and reject unexplained additions/removals.

Crucially, unchanged direct data-directory entries are not a complete loader
proof: import names/thunks, exports, TLS, relocation targets, load-config fields,
exception/debug data and related structures can indirectly reference resource
bytes. A complete qualification needs a bounded reachable-loader-data analysis
showing those structures do not depend on changed bytes, or must HOLD unknown
layouts. A shallow directory-range check must not be labeled ALL-invariant
preservation. This is a concrete remaining proof gap in a minimal validator.

Meaningful negative contract tests can be run on self-authored synthetic data
without executing packages: entry-point and each directory/header mutation,
permission changes, raw/RVA shifts and overlaps, growth/span changes, non-resource
data, gaps/overlay, ambiguous fuse wires, extra/duplicate resources, incorrect
ASAR paths/hashes, unexpected icon/version values, and signed/certificate-bearing
images must be rejected. Serializer output parity and real-image loader graph
coverage are separate tests; neither has been run here.

Recommended smallest deliverable now
Keep production full-byte equality/HOLD. Add only the pinned ingredient manifest,
an input collector with explicit build-only provenance, and independently tested
strict invariant assertions for the future producer boundary. Implement no
normalized-admission flag or receipt-based bypass. A later producer can be enabled
only after complete expected-byte replay, input binding, installed dependency
verification, loader-invariant coverage, and real-image parity evidence exist.
The current missing original EXE/receipt/ASAR prevents proving those final steps.

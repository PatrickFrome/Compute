Scope and API assessment
The public generic API compares immutable bytes with caller-declared name/IID,
labels this declared scope, and retains SOURCE_REQUEST_BINDING_NOT_DERIVED. The
source wrapper rederives the requester through the fixed parser; it requires a
selected direct SHA256 identity and exact source version, package name, archive
digest and manifest binding. It accepts no caller verified flag or request JSON.
Only the supplied archive-byte obligation can be discharged. Phase/profile,
bootstrap/client, custody and installed-output obligations remain missing.

ZIP parsing accounts for every accepted physical range, compares raw local and
central names/flags/method/metadata, checks signed/unsigned descriptors, rejects
overlaps/opaque gaps, and fully decompresses each accepted member with bounded
output, EOF, exact size and CRC checks. The implementation inventories raw modes,
attributes and metadata hashes and never extracts files. Unsupported profiles
refuse rather than normalizing ambiguous layouts.

The pure API hashes and parses the same immutable bytes. The CLI's regular-file
reader additionally checks object identity before/open/after the bounded read.
Neither establishes future path custody, installed namespace alias/reparse
safety, or installed tool identity; those are explicitly unqualified. No new
production gate/admission, trust root, release signature exception, installer,
or downloaded-code execution is introduced by this helper.

# Recovery directory custody: source interface and mount requirements

Status: **HOLD**. The installed Host now composes the authenticated recovery
service when its original verified bundle contains the prepared runner pair.
Legacy bundles and unsupported attached recovery profiles keep it unmounted.
Native backup/restore effects and selector registration remain unreachable:
there is no genuine directory issuer in the original Job owner. Windows build
and execution are **NOT RUN**.

## Existing authority and the new prerequisite

`native-coding-recovery-directory-lifetime.mjs` resolves the exact original job,
server dispatch and recovery phase from their existing private registries. It
compares the six original server binding fields, signal, retained deadline and
phase token before invoking their original synchronous vetoes. Public lifetime
factories, copied records, native-looking JSON and caller callbacks do not supply
custody. `beginOriginalRecoveryDirectoryCustody` then calls the existing fixed
`native_recovery_original_directory_custody_required` refusal. The producer waits
for it before connecting a source pool or performing filesystem/native effects.

`owned-protected-backup-root.mjs` remains read-only. Without an original sealed
registration it refuses before REGISTERING, encryption, identity-store writes or
`mkdir`. Even a sealed READY selector remains an observation; it cannot bypass
the producer's native custody refusal. Existing recovery vetoes remain required.

## Internal native mechanics

`native/browser-guardian-scm/recovery-directory-handles.hpp/.cpp` is compiled in
the existing static original-Main source-set. It has no NAPI entry, arbitrary
path acquisition, separate helper executable, signing key, wire permit or
positive authorization export. Its binding strings are correlation only.

The interface consumes borrowed original handles, duplicates and compares the
exact native opens, and strengthens their sharing with `ReOpenFile` on the
original object. The retained and exclusively created opens require
`FILE_READ_DATA` / `FILE_LIST_DIRECTORY`, as well as metadata rights: metadata-only
opens do not participate in share checks. There is no attributes-only fallback.
It records volume/file/birth identity and checks reparse and
case-sensitive state. A retained direct child is required to keep each
directory nonempty: restrictive sharing alone does not exclude an
attribute-only empty-directory junction conversion. Raw native identity is
diagnostic; it is not an admitted replacement for the existing JavaScript
filesystem-identity digest.

## Private component in the original RunCore owner

The existing single C# assembly in `codex-cli-job-runner.ps1` now contains a
private `RecoveryDirectoryScope` branch of `MetaengineCodexJob.RunCore`. It
acquires object-relative restrictive holds from original directory/ancestor/
anchor handles, validates the fixed backup leaf and parent, and keeps the
original Job in that same helper process. It never duplicates the Job into a
surviving external holder.

For an observed stopped native CREATE event, the branch retains the original
process object, transfers every held directory/anchor open into that worker,
and compares the copies back before Resume/Continue. Debug calls stay on the
creating OS thread. Immutable original slot objects bind process birth and
local generations; consumed slots and PID tombstones cannot be reused.
Unknown transfer or event work revokes the branch and quarantines its opens.
An exit event must be continued and the independently duplicated process
handle signaled before cleanup can count that worker joined. Job accounting
and every original I/O task, including the control reader, must also join.
Pending/replaced control tasks are not discarded to claim a successful close.

This is an unarmed source component, **not a genuine issuer**. Public `Run` and
`RunPolicy` still pass a null recovery bundle. There are no constructor call
sites for either private `OriginalRecoveryBundle` or
`OriginalRecoveryBirthCoverage`; a bag of nonnull object fields is not a native
authentication/lifetime producer. The JS effect refusals and selector HOLD
remain. No new PowerShell entry, wire permit, signing key or helper binary was
introduced.

Debug events guarantee an event-local pre-user-mode stop, but a nested debug
chain or broker-created process can escape coverage. Job totals checked after
exit cannot prove that an unobserved descendant never ran. Workers can also
close/reuse their own copies between readbacks. Enforceable complete birth and
continuous-retention provenance are therefore still missing. This branch
passes exceptions unhandled; it does not invent an attestation for the initial
loader breakpoint. A cancellable original control-reader join is also missing.

The portable tests execute only exact extracted scalar expressions and one
straight-line source branch with synthetic call boundaries, plus structural
contracts. They do not compile or execute C#. C# compilation, interop ABI and
Windows execution remain **NOT RUN**.

## Available installed source composition

The offline inventory now admits exactly
`runtime/native-coding/codex-cli-job-runner.ps1` and
`runtime/native-coding/manifest.json`, together or neither. Their original
verified-package registry snapshot retains immutable runner and PostgreSQL
tool pins. This uses the existing offline bundle/ASAR binding, without another
trust root or a third private-native-tools component. Build staging prepares
once; beforePack verifies and reuses the same bytes rather than recompiling a
potentially different assembly. The installed Node controller selects only
that original registry result, its own fixed module/Node placement and those
fixed paths, both before launch and after helper ready. Explicit paths/hashes,
foreign registry instances and readable source-layout fallbacks do not select
the installed branch.

The fixed `native-coding-recovery-installed-composition.mjs` is imported by
production `runtime-host.mjs`. It reuses the original Host OS reader pair,
protected connection and immutable tool pins. It does not fabricate a Main W76
identity: a branded Host observer resolves the exact authenticated service job
and original Main phase, then uses the existing monitored W61 own-PG reader.
Every original query remains joined, with currentness checked before the next
query. Unsupported attached DB/login/password profiles leave recovery unmounted
and preserve the existing PG/API.

The service's inert authenticated-job facet is registered only after the fixed
device signature/current ADMIN verifier, original phase acquisition and lifetime
take succeed. The server dispatch registry alone predates authentication and is
insufficient. Cancel/expiry/close/finish retire the facet without releasing
unfinished cleanup. Neither facet nor observer supplies native custody. The
actual producer and standalone native adapter still call the real fixed HOLD.

The sole creation primitive uses a literal `protected-backup-root-v1` leaf and
exclusive `NtCreateFile(FILE_CREATE)` relative to an original retained parent.
It retains that same returned child; it does not mkdir then reopen, adopt a
collision, repair an orphan or select another parent. The new child remains
unanchored and unusable until the original issuer supplies an original direct
child anchor. This primitive itself performs creation, so only an authenticated
native issuer may call it after acquiring all required parent custody. The
current JavaScript selector does not call it.

Operation tickets and exact process/Job worker tickets track original joins.
Revocation prevents new work; cancellation, timeout and a callback-shaped claim
do not prove completion. Worker transfer duplicates the held opens into the
original process and compares the duplicate back. Unknown or abandoned work
retains/quarantines handles rather than reporting a drained operation. These
mechanics do not prove that a production worker or every descendant received
custody before it could act.

## Required production mount

The following work is still required before either fixed HOLD may be removed:

1. Extend the existing authenticated original-Main/native Host path with a
   private issuer that resolves the original request/job, current W74 Owner,
   original Host process and W76 own-PG birth. Do not accept caller paths,
   numeric handles, helper path/hash pairs, proof callbacks or JSON as admission.
   The issuer must own the original namespace handles and their acquisition
   provenance, rather than opening names after a final JavaScript check.
2. Retain the backup root, PGDATA and complete necessary parent chains before
   the first effect. For registration, also retain identity-store mutation
   ancestry and original state parent before REGISTERING or temporary identity
   files. Pin ACL/security state through the effect interval. The native
   mechanics do not issue ACL/Owner authority or prove ancestry completeness.
3. For creation, obtain missing fixed parents relative to retained originals,
   return and retain the same new objects, and publish the existing encrypted
   registration only under that custody. A crash, pending REGISTERING or
   orphan/collision remains HOLD; no automatic adoption or trust-root repair.
4. Pass custody to every effectful worker before resume, through the original
   runner/controller registry and original Job. Retain copies across helper or
   Host death and descendant lifetime. The present prepared runner inherits
   only its three stdio handles; this change does not implement that handoff.
   Do not duplicate a helper-owned Job into a surviving Host: an extra Job
   handle can defeat `KILL_ON_JOB_CLOSE` when the helper dies. The eventual
   issuer must preserve the original Job owner's crash behavior, for example
   by co-locating these mechanics with that owner and qualifying the handoff.
5. Bind cancellation, expiry and Owner/Host replacement to immediate revoke.
   Release only after the original processes/Jobs, pipes, SQL operations,
   filesystem completions and phase/send callbacks physically join. Request
   finish or cancellation must not destroy the cleanup owner. Unknown settlement
   stays quarantined and blocks retry; a late callback cannot reopen admission.
6. Connect the mounted service's exact authenticated job and current Owner/own-PG
   observations to the missing native issuer. The available fixed composition,
   prepared package selection and original service facet do not establish kernel
   handle custody. Host-generation veto callbacks only remove readiness.
7. Supply genuine native producers for the private RunCore component: original
   authenticated namespace/lifetime custody, enforceable pre-execution birth
   coverage and continuous per-worker retention, qualified loader handling and
   cancellable control joins. Bind the helper-owned scope to the exact original
   authenticated service facet and controller process registry. The unissued
   private component, three-stdio public inheritance list and Job membership do
   not provide that handoff or authorize recovery.
8. Qualify the static Windows build and real kernel/filesystem behavior,
   including directory sharing, attribute/reparse changes, live PostgreSQL
   compatibility, process inheritance and all crash/join paths. Linux modeled
   tests cannot qualify these properties.

## Evidence boundaries

The Linux C++ model compiles the actual native mechanics with a deliberately
simulated Win32 object boundary. It independently models opens, share conflicts,
path replacement and relative creation. Its result is
`SYNTHETIC_NATIVE_MECHANICS`, `windows_native_execution: NOT_RUN`,
`physical_authority: false`, `authority_effect: false`. Request and producer
tests separately check original-registry refusal and zero effects after final
path observations. No real database, installed directory or service is used.
The crash model also confirms two unsupported counterexamples: a surviving
external Job duplicate suppresses last-handle-close termination, and Job
membership without per-descendant directory copies leaves a namespace gap.
Their expected failure is reported as `COUNTEREXAMPLE_CONFIRMED`, never as
architecture acceptance or evidence that an issuer exists.
It additionally exposes worker self-close after the last readback and the
metadata-only share-mask bypass. Its sharing checks now require both opens to
have participating data/execute/delete access, matching the documented
filesystem algorithm. The older unconditional modeled sharing rule was too
strong and has been corrected.

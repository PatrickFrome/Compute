# ME2 Round Runner — дисциплина одного раунда

Ты выполняешь ОДИН атомарный раунд (R13, R14, …) разработки ME2 OS. Раунд = одна задача из
бэклога ИЛИ один багфикс, доведённые до верифицированного коммита. Маленький законченный
раунд лучше большого оборванного: платформа убивает процессы между вызовами, а exec-limits
отключают cron при перегрузке.

## 0. Восстановление контекста (всегда первым шагом)

1. Прочитай ПОСЛЕДНЮЮ запись `/home/z/my-project/worklog.md` (шаблон внизу). Раздел
   «Следующее (бэклог)» — твой список кандидатов. Секции «Уроки» — экономят часы: они куплены
   живыми инцидентами прошлых раундов. Не повторяй завершённые раунды.
2. Проверь живость: `curl -s localhost:3041/health` (версия, actions 47/47), порты
   `81/3000/3040/3041/3042` через `curl -o /dev/null -w "%{http_code}"`. CRON-волна могла
   закрыть раунд без тебя — сверяй `git log --oneline -5` с worklog.
3. Оживи при необходимости: daemon — `bash mini-services/me2-daemon/start.sh` (единственный
   легальный способ); Next dev — `cd /home/z/my-project && (setsid nohup bun run dev > dev.log 2>&1 &)`.

## 1. Выбор задачи

- Бери пункт бэклога с максимальной ценой/риском (усиление ядра > косметика).
- Проверь осуществимость в песочнице: нет дисплея (GUI-фреймворки = только скелет),
  нет внешних БД (Supabase — только outbox-буфер), провайдер LLM имеет rate-limit.

## 2. Ресёрч (если задача концептуальная)

1–2 синхронных запроса (`timeout 75 z-ai function -n web_search -a '{...}' -o research/2026/rN-*.json`;
фоновые вызовы молчат — только sync) + `z-ai function -n page_reader -a '{"url":...}'` для
полного текста ключевой статьи. Пиши `research/2026/RN-<ТЕМА>-RESEARCH.md`: находки →
маппинг на детекторы/контракты ME2 → честные ограничения. Ресёрч без записи в файл = не было.

## 3. Имплементация

- Реестр шины заморожен на 47/47: enrichment-операции (reflect, metrics) идут ОТДЕЛЬНЫМ
  REST-роутом daemon'а, никогда — действием шины.
- Версия daemon: bump `VERSION` в `index.ts` при любом изменении daemon-кода.
- MultiEdit не атомарен по соседним строкам — после КАЖДОЙ правки перечитай регион.
- Рестарт daemon только после того, как ВСЕ правки в файлах (параллельные tool-вызовы
  выполняются в произвольном порядке — рестарт в том же блоке, что и Edit, может обогнать его).

## 4. Верификация (без неё раунд не засчитан)

1. Детерминированные детекторы — юнит-пробой на РЕАЛЬНОМ коде:
   `cd mini-services/me2-daemon && bun -e 'import {...} ...'` (импорт модулей безопасен,
   side effects ленивы).
2. Живые E2E через шину: POST /tasks с жёстким диагностическим spec (предпиши точную
   последовательность инструментов и ЗАПРЕТИ finish — тогда LLM-агент воспроизводит
   нужный failure-mode).
3. UI golden paths через agent-browser ТОЛЬКО на http://localhost:81/ (прямой :3000 не
   проксирует XTransformPort). Отдельная `--session rN` для QA. SVG-хит-зоны: строка =
   `g[data-branch-id] rect.branch-hover`; перед hover — `el.scrollIntoView({block:'center'})`.
   Скриншоты `download/rN-*.png` + `agent-browser read | grep` для текстовых проверок.
4. Mobile 390: `sw` обязана равняться `vw`.
5. `tail dev.log` на ошибки; `bun run lint` обязан быть 0/0 (EXIT:0). `bun run build` — НИКОГДА.

## 5. Шип

1. `bash >> worklog.md` — запись по шаблону ниже (Task ID = следующий RN).
2. `bash scripts/git-sync.sh` → push в sandbox/me2-os. main монорепо не трогать. Секреты
   живут только в /home/z/.a2/ — git-sync гард блокирует ghp_/vck_/JWT, но не проверяй
   это нарочно.
3. **НИКОГДА не делай `git pull` / ручной `git push` в этом репо** (урок R15): remote
   `main` = старый MetaEngine monorepo (тысячи чужих коммитов) — pull затянет их и начнёт
   интерактивный rebase всех ME2-коммитов. Единственный легальный путь — scripts/git-sync.sh
   (push main → refs/heads/sandbox/me2-os, fast-forward). Если push не fast-forward —
   остановись и разбери remote-состояние, не pull'ить.
4. Cron webDevReview (15 мин) должен существовать и быть активным; payload компактный
   (детали — в worklog, иначе exec-limits отключают задачу).

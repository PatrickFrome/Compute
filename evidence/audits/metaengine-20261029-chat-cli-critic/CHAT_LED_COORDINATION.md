# Protected chat-led projects

## Implemented source path

An explicitly prepared protected profile with schema
`metaengine.native-coding.seed-profile.v2` and `coordination_mode: CHAT_LED`
uses the existing private seed admission operation. It creates a READ_ONLY
browser PLANNER root and the same verified native IMPLEMENTER/CRITIC permits.
Legacy v1 profiles retain their CLI IMPLEMENTER root. No existing profile,
request, installed runtime, credential or protected file is converted silently.

The existing authenticated project spawn function routes IMPLEMENTER/CODER
proposals in this project to an available native permit. It checks project,
goal, profile, device, epoch, artifact, PostgreSQL, expiry and worktree fences.
Capacity waits preserve a proposal and cannot fall back to a browser worker.
Only the existing W30 allocator can grant a lease. Explicit CRITIC proposals
are rejected: the existing reconciler admits independent review for the exact
writer subject, rather than leaving an impossible review proposal pending.

After a committed checkpoint, eligible writer permits can be traced recursively
through existing commit records to the original seed permits. Child enqueue uses
the selected permit's base SHA, not the chat planner's older lease SHA. The Host
commit reader accepts only the specific v2 CHAT_LED profile in addition to v1.
The UI receives a readonly mode label from the verified Host profile catalog.
The chat prompt explains delegation, automatic independent review and the need
to await verified completion/checkpoint evidence.

## Migration and boundaries

The additive migration verifies exact predecessor/current function bodies and
security/search-path settings, checks the exact prior/current profile constraint,
and is registered in local runtime migrations and the fresh source manifest.
The earlier capacity migration recognizes the reviewed chat profile validator;
installer reapplication restores the chat extension inside the same transaction.
No historical migration or main branch is edited. Private permit selection is
not granted to public, anon, authenticated or service_role callers.

## Evidence and gaps

- Real disposable PG17 seed/project suite: 22 passed. Includes an actual browser
  claim, two native child admissions, exact replay, capacity wait, foreign task,
  revoked profile, legacy v1 and unreviewed-upgrade negatives.
- Combined project runtime and PG qualification after the review guard: 82 pass.
- UI/goal/seed focused suites: 74 pass; TypeScript noEmit passed.
- Fresh-source/migration-plan tests: 14 pass, 3 environment-dependent skips.
- Existing native continuation and commit-rotation suites on PG17: 19 pass,
  including independent ACCEPT/REJECT, bad critic digest rollback and rotation.
  These latter suites qualify their existing SQL fixtures, not the entire new
  chat-led installed route or actual model execution.

All enrolled identities, Windows images, native process/canary and ACL witnesses
in these SQL tests are generated fixtures. The protected v2 profile producer
on the user's machine has not been integrated or run. Full chat-led Windows
execution, resumed browser parent after native commit, rotated-permit handoff,
installer and live model qualification remain open. Do not describe this as a
completed autonomous client or silently enable v2 in an existing installation.

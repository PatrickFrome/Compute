# R9 · Ресёрч улучшений: Reflexion-контур, профили полосы, Saga-перспектива

Дата: 2026-09-22 · Итерация R9 long-run · Триггер: «делай ресёрчи по улучшениям» (4-я итерация инструкции)
Метод: web-search (3 направления) + анализ протокола стрима (agent-browser streaming.md) + реализация в этой же итерации.

## 1. Источники (web-search, топ-находки)

### 1.1 Reflexion / само-коррекция агентов (research/2026/r9-reflexion.json)
- **Reflexion** (оригинал): агент генерирует вербальную рефлексию о провале → сохраняет как
  **эпизодическую память** → следующая попытка стартует с ней («self-reflection → update memory →
  reset environment → new trial»).
- **Agent Self-Correction: From Reflexion to Process Reward** (05.2026): чисто внутренняя
  самокоррекция без внешнего сигнала часто **не работает**; работают заземлённые (grounded)
  подходы — рефлексия обязана опираться на фактическую ошибку (у нас: error-текст + шаги + бюджет).
- **Multi-Agent Reflexion** (06.2026): рефлексии как память улучшают и одиночные, и мультиагентные прогоны.
- **Arthur/2026**: self-correction loop = охрана прогонов: провал → разбор → replan ДО следующей попытки.

**Вывод для ME2**: у нас уже есть половина контура — lineage (parent_id, R6) и честные ошибки.
Не хватало звена «провал → диагноз → память для потомка». Рефлексия должна быть
**детерминированной** (по классу ошибки) — LLM-вербализация это tier-2 (бэклог).

### 1.2 Saga/компенсация (research/2026/r9-saga.json)
- **Pattern: Saga** (microservices.io): локальная транзакция упала → сага исполняет серию
  **компенсирующих транзакций**, семантически отменяющих завершённые шаги.
- Ключ: rollback БД ≠ компенсация; для side-эффектов нужен явный map «действие → его undo».

**Вывод для ME2**: шина MUTATION-действий идеальный кандидат на COMPENSATION_OF-map:
BROWSER_OPEN↔BROWSER_CLOSE, TASK_CREATE↔TASK_CANCEL, TASK_PAUSE↔TASK_RESUME,
AGENT_PAUSE↔AGENT_RESUME. В R9 не реализовано (действия атомарны, провалов «после шага» почти нет) —
**спека на M3+** (когда появятся многошаговые MUTATION-сценарии/скрипты поверх шины).

### 1.3 Адаптивная полоса стрима (research/2026/r9-abr.json + streaming.md)
- ABR-практика (08.2026): качество/частота адаптируются **по измеренной полосе зрителя**,
  не по догадкам; fps влияет на CPU, полосу и glass-to-glass задержку одновременно.
- **streaming.md (локальная докa агента)** — решающие факты:
  - `pacing` (push|ack) и `maxFps` — **per-client** настройки; URL-параметры покрывают открывающий кадр,
    `{"type":"config",...}` работает на лету без реконнекта;
  - ack-пейсинг: сервер держит ≤1 кадра в полёте, клиент эхом шлёт `{"type":"ack","seq"}` (cumulative);
    застрявший клиент после возобновления получает **текущий** кадр, а не 10 секунд истории;
  - «constrained preview usually wants both» (pacing=ack + maxFps).

**Вывод для ME2**: профили полосы — это не «новый стрим», а **правильное использование
уже имеющихся per-client ручек**. Качество jpeg (env AGENT_BROWSER_STREAM_QUALITY) — глобальное,
в per-client профили не входит — отметить как ограничение.

## 2. Реализовано в R9 (v0.9.0 daemon / консоль)

### 2.1 Reflexion-контур (daemon + ВЕТКИ)
- `tasks.reflection TEXT` (миграция PRAGMA table_info → ALTER, паттерн parent_id).
- `worker.ts: buildReflection()` — **tier-1 детерминированный диагноз** по классу ошибки:
  `budget_exhausted | provider_unavailable | workspace_path | protocol_violation | runtime_error`
  → {cause, what (по-русски), hint (урок для повтора), error, steps/max_steps, at}.
  Пишется в обоих путях провала (max_steps_exhausted + исключение).
- **Эпизодическая память**: `parentMemory()` — TASK_RETRY-потомок при lease получает
  первым сообщением «ПРЕДЫДУЩАЯ ПОПЫТКА ПРОВАЛИЛАСЬ: причина + урок» (emit TASK_LEASED retry_memory:true).
- TASK_RETRIED событие несёт `has_reflection` (оператор видит, что ретрай осмысленный).
- Консоль: блок «рефлексия» в portal-tooltip ВЕТКИ (cause-бейдж + what + ↳hint) и
  **кнопка ↻ на строке FAILED/CANCELLED** — TASK_RETRY в один клик (stopPropagation, tooltip-подсказка).

### 2.2 Профили полосы стрима (консоль, ВЕТКИ → каст)
- Сегмент-контрол `макс | баланс | эконом | авто` рядом с «консоль (N)»:
  - **макс** = push, 12 fps — минимум задержки для руля;
  - **баланс** = ack, 8 fps (новый дефолт — нет очередей при лаге);
  - **эконом** = ack, 2 fps — слабая сеть;
  - **авто** = ack, старт 8 → ежесекундная адаптация потолка по KB/s (600→2 / 250→4 / 100→8 / иначе 12),
    config-сообщением без реконнекта.
- Клиент теперь **эхом ack-ает seq** в ack-режиме (без этого сервер молчит после первого кадра).
- Статус-бар кадра: `● fps · КБ/с · возрастms` — полоса видна оператору (замер: base64×0.75).
- Смена профиля = реконнект с новыми URL-параметрами (покрывают открывающий кадр).

## 3. Верификация (живая, :81)
- Профили: баланс 8fps/ack → эконом 2fps → макс push 12fps → авто (адаптация по KB/s) — кадры идут во всех.
- Reflexion: заведён провал (макс_шаги=2, задача на 3+ шага) → FAILED с reflection.budget_exhausted →
  tooltip показывает блок рефлексии → ↻ → ретрай создан (parent_id, has_reflection:true) →
  в events TASK_LEASED retry_memory:true → агент с памятью о провале родителя.
- Lint 0/0. Snapshot tasks несёт reflection автоматически (SELECT *).

## 4. Бэклог (приоритизирован)
1. **Tier-2 вербальная рефлексия**: LLM-вызов при провале (дорогой, но глубокий диагноз спеки) —
   флаг на агенте, не на дефолтном пути.
2. **Saga COMPENSATION_OF** на шине (спека §1.2) — при многошаговых MUTATION-сценариях.
3. **Per-client качество jpeg** — сейчас env-глобально; запросить фичу в agent-browser или
   переконфигурировать screencast_start'ом (формат меняется на лету — «sniff the bytes»).
4. M3 Tauri 2 externalBin (переносится из R7/R8), SQL-миграция me2_evidence (ждёт оператора).
5. Компакт-режим ВЕТКИ для 50+ задач (виртуализация строк графа).

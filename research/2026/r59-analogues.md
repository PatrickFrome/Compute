## 1. «Аудит как цикл» — как это делают эталоны

R59 перевёл RLS-аудит (R58) и сверку реестра RPC из «разовых проб раунда» в постоянный
внутренний цикл daemon'а (20 мин, события только на переходах). Разбор эталонных
reconcile-петель:

**Kubernetes controller reconcile.** Контроллер бесконечно сводит desired state (манифест)
с observed state (живой кластер). Ключевые механики, которые мы взяли:
- **Level-triggered поверх edge-triggered**: каждый тик сравнивает ПОЛНОЕ состояние, а не
  ждёт «сообщений об изменениях» — пропущенное событие не портит результат (мы не зависим
  от доставки: цикл сам пересчитывает факт psql-каналом).
- **Resync period**: полный пересбор периодически даже без изменений (наш 20 мин — их
  resync; кэш 60с модулей — их informer-кэш).
- **События только на переходах** (edge-уведомление поверх level-сравнения): `kubectl get
  events` шумит только аномалиями. Наш `transition()` в src/self-audit.ts — точный этот
  узор: PASS из unknown молчит, FAIL входит — RLS_AUDIT_FAIL/RPC_RECONCILE_FAIL,
  FAIL→PASS — *_RECOVERED. «Тихо = здорово» — река событий не засоряется ровным PASS.

**AWS Config rules.** Периодическая запись конфигурации ресурса + правила соответствия;
compliance-статус хранится КАК ДАННЫЕ (не «в голове оператора»), с временной серией.
Наш эквивалент: вердикты рls-аудита/сверки уходят в hash-chain событий (emit) — временная
серия соответствия строится сама; JSON-вердикты — данные, пригодные для ретроспективы
(«когда реестр начал дрейфовать?»).

**Terraform drift detection (`terraform plan -refresh-only`).** Ожидаемое состояние в коде
(= наши sql/0003+0004 и r52-rpc-registry.json в репо), факт запрашивается у провайдера
(= живой каталог Postgres), diff отдаётся человеку, но ничего не меняет без явного apply
(= наш Zero-authority: read-only, на шину и решения не влияет). Поимённые списки
missing/extra/tier_mismatch — их planned changes.

**pg_dump --schema-only diff / git fsck** (уже отмечено в R58): сверка с «ожиданием как
данными». R59-добавление: sha256-хеш отсортированного множества `name|tier` (у нас
`337ccab1d17f` для 243 RPC) — компактный «fingerprint реестра»: одно число для
сравнения «вчера vs сегодня», как content-addressable snapshot.

**Вывод:** наш контур R59 = минимум из всех четырёх: level-сравнение полного состояния
(K8s), статус как данные в цепочке (AWS Config), diff-списки без права мутации (Terraform),
хеш-fingerprint (fsck). Ничего лишнего — 148 строк bash + ~120 строк TS + ~90 строк TS.

## 2. Extension host VS Code — механика изоляции (приготовление R60+)

Пробел из мастер-дока (кандидат R60+). Как устроен канон:
- **Отдельный процесс** (exthost): краш расширения не валит workbench; перезапуск exthost
  дешевле рестарта редактора. У ME2: pool/worker-процессы уже отдельные; skills грузятся
  в daemon-процессе — вот пробел.
- **API-поверхность вместо доступа к API ядра**: расширение видит только `vscode.*`,
  не может require внутренние модули. ME2-маппинг: skills/policy.json уже описывают
  capability-гейты (tierForRole, policyAllows) — идея R60: гонять skills в дочернем
  процессе с урезанным набором (spawn с prlimit — канон sandbox.ts: `--as=1GiB
  --nofile=256 --core=0`), обмен через JSON-RPC/stdio, NOT через прямой импорт.
- **Activation events**: расширение грузится по событию (команда/язык/файл). ME2:
  skills-каталог уже лениво резолвится; добавить «activation по событию шины».
- **$initialize handshake + ping**: exthost подтверждает живость; вечно-THINKING ловится
  супервизором — наш agentchat-супервизор (G2) уже такой.
- Урок безопасности VS Code: «расширение недоверенно по умолчанию» — наш non-bypass
  инвариант строже, чем у аналогов (пункт 8 инвентаря).

## 3. Workbench-лэйаут — механика (приготовление R60+)

- VS Code: сетка частей (activity bar / sidebar / editor groups / panel / status bar),
  каждая часть сворачиваема, размер персистится в state.vscdb (SQLite key-value).
- Cursor сохраняет workbench 1:1 и добавляет AI-панель как «editor group» — то есть
  НОВОЕ не ломает канон лэйаута, а встраивается в него.
- ME2 /ui сейчас: grid «флот | река | зеркало», панели фикс. Минимум канона для R60:
  (а) collapse/expand секций (details/summary — без JS-библиотек), (б) персист
  состояния в localStorage (не канон SQLite — но /ui self-contained и без сборки;
  SQLite-персист лэйаута — забота daemon'а, ключ в meta-таблице), (в) порядок секций
  не менять в R60 — только видимостью и высотой (урок R12/R16: не плодить слоёв).

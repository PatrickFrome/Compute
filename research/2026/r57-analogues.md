# R57 · Ресёрч аналогов: GoTrue-токены в клиентах и демонстрация RLS-матрицы

Дата: 2026-09-23 · Метод: web_search 429 (7-я сессия подряд — не амплифицировал; анализ по накопленной
базе знаний + живые пробы облака R57). Контекст: реализован gotrue-канал (настоящий GoTrue access_token
сервис-аккаунта в daemon, кэш+refresh+single-flight+анти-шторм; в UI уходит только короткоживущий JWT) и
полная RLS-матрица в /ui (anon отказ 42501 ✓ · authenticated читает 206/200 ✓ · service пишет ✓).

## 1. Короткоживущий user-JWT в клиенте: кто как держит

| Аналог | Паттерн | Что взято / что НЕ взято |
|---|---|---|
| **Supabase JS SDK** | `autoRefreshToken`: refresh за ~5 мин до exp (120-секундный буфер до отрисовки), в памяти сессия, refresh_token в storage | Взято: refresh-заблаговременность (у нас 120с буфер) + ре-логин при отказе refresh. НЕ взято: хранение refresh_token в localStorage браузера — наш клиент-refresh живёт в daemon (BFF) |
| **Firebase Auth** | ID-token 1ч, `getIdToken()` возвращает кэш, авто-обновление фоном; `onIdTokenChanged` | Взято: «кэш-первый» (сеть только при exp-буфере) — наш gotrueToken() идентичен по форме |
| **VS Code Authentication API** | `getSession()` возвращает сессию с access_token; refresh в провайдере; токены — через safeStorage, НЕ в рендерере | Взято: «единая точка refresh» (у нас daemon = единственный, кто логинится); UI получает уже валидный токен |
| **Cursor** | Рендерер не держит DB-креды вообще; backend-прокси | Подтверждает наш service_proxy как дефолт данных; gotrue — только для демонстрации RLS |
| **Cognito/Amplify** | silent refresh + refresh-token rotation | Ротацию НЕ взяли (GoTrue одноразовый refresh_token без ротации в этом режиме); анти-шторм свой |
| **Chromium OS-token-service** | один сервис обновляет токены, рендерерам —hints only | Архитектурное подтверждение: refresh в едином доверенном процессе |

## 2. Заголовки PostgREST: каноническая форма запроса под юзер-JWT

Живая проба R57 подтвердила канон: **apikey = публичный ключ (publishable/anon), Authorization = Bearer
<user-JWT>**. Bearer поверх не-JWT publishable даёт ложный 401 (фиксация в R56); apikey=gotrue-JWT — тоже
неверно. Это ровно документированный контракт PostgREST/Supabase: apikey выбирает роль-пул,
Bearer — юзера. Панель /ui и скрипты проб используют `probe(tok, key)` — два заголовка раздельно.

## 3. 42501 (insufficient_privilege) — семантика

- PostgREST отдаёт 42501 как «permission denied for table» с hint'ом про GRANT — это ОЖИДАЕМЫЙ
  fail-closed ответ для роли без гранта, а НЕ ошибка интеграции.
- Аналог: Supabase Studio Table Editor показывает RLS-ошибку пользователю verbatim, не ретраит.
- Взято: панель трактует 42501 как успех демонстрации гейта («anon ОТКАЗАН ✓»), ретраи отсутствуют.
- Анти-паттерн зафиксирован: автологин-шторм при 401 → у нас anti-storm 30с + single-flight.

## 4. Полная матрица авторизации как продукт (новый узор)

Студия/консоли аналогов показывают либо данные, либо ошибку. Наш R57-узор — **трёхстрочная живая
матрица в одном месте**: `anon — отказ ✓ · authenticated — чтение ✓ · service — пишет ✓`.
Ближайший аналог — «Auth policy debugger» Supabase Studio (появился 2024): он проверяет политику
симуляцией; у нас — реальные пробы тремя ролями на живой таблице (честнее: нет симуляционной модели,
есть облако). Зафиксировано как узор «матрица как демонстрация» для документации системы.

## 5. BFF (backend-for-frontend) вокруг короткоживущих токенов

Паттерн BFF: клиентский секрет вообще не покидает сервер, фронт получает cookie/токен с минимальным
сроком. Наше расщепление честнее для аудита: данные — через daemon-прокси (ключи не покидают сервер),
RLS-демонстрация — публичные/юзерские токены в UI (они по природе не секрет). Это двойная честность:
безопасность (нет секретов в UI) + доказуемость (гейт реально пробуется из браузера).

## 6. Осознанные НЕ-заимствования

- localStorage для refresh_token (Supabase JS дефолт) — XSS-поверхность; наш refresh живёт в daemon.
- Симуляция политик (Studio debugger) — не нужна, есть живая таблица.
- Тихий ре-логин в цикле (Amplify) — анти-шторм 30с + честный last_error вместо бесконечных попыток.
- Хранение access_token в cookie консоли :3000 — токен и так короткоживущий, панель перезапрашивает.

## 7. Применение в ME2

1. gotrue-канал — закрыл последнюю строку RLS-матрицы; «чтение из UI с RLS-гейтом» (R53-план) теперь
   демонстрируется ПОЛНОСТЬЮ: обе стороны гейта живьём.
2. Anti-storm/single-flight — канон G11 (полосы+breaker) распространён и на GoTrue-канал.
3. Для R58+ кандидат: механизм «policies как данные» — таблица ожидаемых грантов/политик (sql/0004
   уже де-факто источник) → самопроверка daemon'ом (сравнить pg-гранты через psql-канал с ожидаемыми).

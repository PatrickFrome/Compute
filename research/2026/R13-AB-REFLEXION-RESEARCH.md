# R13 Research — Рандомизированный A/B авто-рефлексии · 2026-09-22

Контекст: R12 закрыл 8 failure-modes. Бэклог: «рандомизированный A/B для метрики Reflexion».
Проблема: observational-метрика R11 («pass-rate с уроком vs без») смещена — авто-уроки получают
не случайные, а все ретраи подряд; сравнение отражает и сложность задач, и эффект памяти.

## Находки web_search (r13-ab.json)

1. **«Agent A/B: Automated and Scalable A/B Testing on Live Websites» (ACM, Apr 2026)** —
   A/B-тестирование с LLM-агентами как полноценная методология: назначение групп + метрики +
   симуляция персона. Подтверждает: рандомизация обязательна для causal-вывода об эффекте.
2. **«Adaptive Memory Admission Control for LLM Agents» (arxiv, Mar 2026)** — контроль ДОПУСКА
   в память агента как отдельный механизм (A-MAC). Наш авто-reflect = решение о допуске урока;
   A/B-гейting этого решения — первый шаг к адаптивному допуску (в перспективе — по результатам A/B).
3. **Spotify Engineering «When Can LLMs Replace Humans in A/B Tests?» (Aug 2026)** —
   рандомизированные эксперименты остаются золотым стандартом; LLM-суррогаты работают «по
   допущению, а не по дизайну». Вывод: измерять эффект памяти на РЕАЛЬНЫХ ретраях с рандомизацией,
   не на суррогатных оценках.
4. page_reader по статье Spotify вернул пустой текст (платформенный лимит извлечения) —
   сниппеты + общая методология достаточны для контракта лаборатории; полный текст — по требованию.

## Контракт A/B (v0.13.0)

- **Назначение**: детерминированный FNV-1a(taskId) → treatment|control (50/50, юнит: 500/500,
  dev 0%). Детерминизм = повторные ретраи того же родителя не перебрасывают группу
  (стабильность единицы эксперимента) + назначение пересчитуемо в /metrics без чтения событий.
- **Тreatment**: авто-LLM-урок при TASK_RETRY (гламуры R11 сохранены: cooldown 10 мин,
  ≤2 in-flight, skip при существующем уроке). **Control**: авто-урока нет; ручной ✦ оператора
  остаётся (честная реальность эксплуатации).
- **Аудит**: TASK_RETRIED несёт `ab_group` навсегда (hash-chain events).
- **Метрика** (/metrics): intent-to-treat — группы по `abGroupOf(parent.id)` независимо от
  факта генерации урока; `control_crossover` = control-родители с ручным уроком (видимость
  загрязнения). Старый observational-блок (with_lesson/without_lesson) сохранён.
- **UI**: чип ВЕТКИ дополнен `A/B T x/y · C z/w [· xN]` (fuchsia/zinc/amber).

## Живая верификация

- Пара проб: p1=tk_mucqbkh6rieqs4 → **treatment** (авто-урок пришёл, source=auto_retry,
  TASK_REFLECTED seq 1324), p2=tk_mucqbkk0ix7sla → **control** (llm NONE, чисто).
- Потомки: treatment-child COMPLETED 4/4 (память урока → успех, второе живое подтверждение
  после R9), control-child FAILED 0/4 — **429 rate-limit провайдера** (2 параллельных ретрая +
  авто-рефлексия = 3 одновременных LLM-потока). Инфра-шум, не дефект A/B → бэклог:
  джиттер/backoff агентов при 429 или лок-шеринг квоты между агентами.
- /metrics: ab {T 1/1 100%, C 0/1 0%, crossover 0}; чип в UI «A/B T 1/1 · C 0/1».

## Честные ограничения

- Единичный сэмпл (n=1 на группу) статистически пуст — накопление идёт на живых ретраях;
  чип и /metrics растут автоматически.
- Intent-to-treat допускает crossover (ручной ✦ в контроле) — счётчик xN делает загрязнение видимым.
- Детерминизм по id означает, что группа «случайна» только между задачами (stratified by id
  space) — при малых n возможны серии одной группы; при n≥50 распределение выравнивается.

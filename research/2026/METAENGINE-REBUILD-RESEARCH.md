## 1. Диагноз: почему METAENGINE Browser «медленный и конфликтный»

Факты из полугода эксплуатации (worklog, миграции, инциденты):

| Проблема | Корень |
|---|---|
| Медленная обратная связь (8×1800ms recapture, capture-бюджеты, heartbeat 794ms–1s) | **Браузерная вкладка как интерфейс агента**: агент = страница чата z.ai, управление = скрейпинг DOM + семантический ввод + обход капч |
| «Конфликтность» (draft-poison 48k, composer_not_unique, action_budget_exceeded, PL poison) | Состояние размазано: localStorage вкладки + память шелла + облако; несколько авторов пишут одну поверхность |
| Ресурс: 20+ вкладок Chromium, 32-tab budget, elastic governor плодит/убивает | N агентов = N полноценных страниц Chromium в одном Electron-процессе |
| DB-as-message-bus: команды через PostgREST RPC, лизинг, PENDING/LEASED | latency каждой команды ≥ heartbeat; гонки lease/binding; SQL-миграции на каждое новое действие (action-allowlist) |
| Хрупкий self-update: Windows E2E, рестарты оператора, sentinel-слепота | Self-forking архитектура: бинарь обновляет сам себя через grace-состояния |
| Схема разъезжается (104 локальных миграций ≠ облако; GRANT-дыры 42501) | Облако как единая точка правды + RLS/гранты на каждый объект |
| Эластичность = дренаж спроса только по TTL lease | Смерть агента не освобождает claim — воркер-вкладка умерла, task LEASED до expiry |

**Главный вывод**: 80% сложности — не в задаче (координация воркеров), а в **транспортном слое** (вкладка-как-агент + облако-как-шина). Пересборка должна убирать именно его.

## 3. Что каждый аналог делает лучше (идеи для заимствования)

### 3.1 Терминальные агенты (ядро нового METAENGINE)
- **Claude Code** (Anthropic): однопоточный **master loop («nO»)** + очередь **h2A** с real-time steering; слоистая архитектура «просто и отлаживаемо»; **subagents** — свежие инстансы со своим контекстом/инструментами/моделью, лид собирает результаты; plan mode → исследование до правок. *Брать: один цикл вместо роя вкладок; subagents с изолированным контекстом; steering в реальном времени.*
- **Aider**: **repo map на tree-sitter** — сжатая карта репо экономит токены; git-native: каждый шаг = коммит; .aiderignore. *Брать: карту кода как общий контекст флота; атомарные коммиты на шаг.*
- **OpenCode**: Go, TUI на Bubble Tea, **75+ провайдеров**, AGENTS.md-конвент, сессии, десктоп+IDE из одного ядра. *Брать: модель-агностичный провайдер-слой (у нас уже есть Vercel AI Gateway key в Supabase!); одно ядро — много оболочек (CLI/TUI/десктоп).*
- **Pi** (Mario Zechner): **418 строк agent loop**, превосходящего «тяжёлые» харнессы; pi-tui — дифференциальный рендер без мерцания; «промпты — это код, .json/.md — состояние»; отказ от MCP в пользу CLI-инструментов. *Брать: минимализм ядра; состояние — файлы, не БД; инструменты = CLI-процессы.*
- **Codex CLI/App** (OpenAI): лид Gartner MQ enterprise-агентов 2026; одна модель интерфейса — app + cloud + CLI + IDE-плагин. *Брать: «один агент, три поверхности».*

### 3.2 IDE-агенты
- **Cursor** (форк VS Code, $29.3B): AI-first поверх привычного UI; Composer. *Брать: не форкать IDE — встраиваться в пользовательскую среду, а не создавать свою.*
- **Windsurf** (Codeium): agent-first «сам планирует и правит» полуавтономно. *Брать: каскад планирование→правка с человеческим чекпоинтом.*
- **Cline**: human-in-the-loop, каждый дифф одобряется; **browser-automation MCP-инструмент** — браузер как инструмент агента, а не дом агентов. *Брать: браузер = инструмент одного воркера (MCP/CLI-вызов), не коллективная память.*
- **Roo Code**: роли/режимы (Architect/Code/Debug) — **архивирован в мае 2026**: урок — ролевые режимы без общей памяти не масштабируются.
- **Kilo Code / Kiro (AWS)**: **spec-driven** — EARS-нотация, specs/steering/hooks; архитектурная согласованность через спеки. *Брать: спека как первичный артефакт; агенты исполняют спеки, а не общаются чатами.*

### 3.3 Локальные/инфраструктурные
- **Continue / Ollama**: приватность и любые локальные модели. *Брать: локальная модель для рутинных ролей (суммаризация, линт-фиксы).*
- **Rust agent-stack 2026** (тренд GitHub Q1-2026): агент-рантаймы уходят в Rust — один статический бинарь, ноль зависимостей; **client-daemon** паттерн (crates.io `agent-browser`: CLI + pure-Rust daemon). *Брать: рантайм = демон, оболочки = клиенты.*
- **CDP напрямую вместо Playwright** (browser-use): отказ от Playwright ради скорости/возможностей; Puppeteer на 15–20% быстрее Playwright на Chromium; headless-фермы плохо скейлятся самохостингом. *Брать: если нужен браузер — тонкий CDP-клиент в Rust-демоне, вкладки на-demand, а не N постоянных.*

### 3.4 Паттерны оркестрации (Microsoft Azure, Openlayer, Confluent 2026)
Продакшен-устойчивы только два: **hierarchical supervisor–worker** и **graph** (зависимости). Blackboard/swarm — дорого и конфликтно. Событийная шина (event-driven) с персистентным логом — стандарт.

## 4. Оболочка: чем заменить Electron (2026 факты)

| Вариант | Бандл | RAM | Старт | Плюсы | Минусы |
|---|---|---|---|---|---|
| **Tauri 2.x (Rust+WebView2/WebKit)** | ~2.5MB (в 20–50× меньше) | **в ~5× меньше**, 75% экономии | **~3.7× быстрее** | Rust-ядро = наш демон в том же бинаре; sidecar-интеграция; автoupdate из коробки; IPC-команды типизированы | WebView ≠ Chromium (два движка: UI в WebKit, автоматизация в своём Chromium через CDP) |
| Wails v3 (Go+WebView) | малый | малая | быстрый | проще Go | экосистема меньше, агент-кода на Go мало |
| Neutralino | ~2MB | малая | быстрый | супер-лёгкий | нет нативного рантайма для тяжёлой логики |
| Flutter Desktop | средний | средняя | средний | единый UI | не веб-стек, консоль придётся переписывать |
| Qt/Slint/egui | нативный | минимальная | мгновенный | максимум скорости | полностью новый UI-стек |
| **Без GUI: TUI + локальный web-консоль** | 0 | минимальная | мгновенный | Claude Code/OpenCode путь; консоль на Next.js УЖЕ есть | нет «браузерного» ощущения |

**Рекомендация оболочки**: Tauri 2 (Rust-ядро + существующая Next.js-консоль в webview) **или** pure-daemon + текущая web-консоль. Electron-слоя с вкладками больше нет — UI не должен держать агентские страницы.

## 5. Целевая архитектура («METAENGINE 2»)

```
┌─────────────────────────── Tauri 2 окно / браузер ───────────────────────────┐
│  Консоль (Next.js, существующая) — флот, задачи, спеки, диффы, логи          │
└──────────────▲───────────────────────────▲───────────────────────────────────┘
               │ WebSocket (локальный)     │ REST
┌──────────────┴───────────────────────────┴───────────────────────────────────┐
│                    ME2 CORE — Rust daemon (один бинарь)                      │
│  • Master loop (nO-подобный, 1 поток) + h2A-очередь steering                 │
│  • Subagent pool: N изолированных контекстов (не вкладок!)                    │
│  • Провайдер-слой: z.ai API / Vercel AI Gateway (ключ уже в Supabase)         │
│    / локальные модели Ollama / любые через OpenRouter                        │
│  • Browser-tool: тонкий CDP-клиент (chromiumoxide) — 1 headless Chromium     │
│    на-demand (капчи, скриншоты, верификация), не дом агентов                 │
│  • Repo map (tree-sitter) + spec-парсер (EARS) + worktree-менеджер           │
│  • Event log: локальный SQLite (WAL) + синдронизация дельт в облако          │
└──────────────┬───────────────────────────────────────────────────────────────┘
               │ дельты/доказательства (не поллинг!)
┌──────────────▼───────────────────────────────────────────────────────────────┐
│  Облако (Supabase как есть): evidence plane, история, дашборды, self-update  │
│  Hot-path команд УБРАН из БД → локальная шина. Облако = журнал, не автобус.  │
└──────────────────────────────────────────────────────────────────────────────┘
```

**5 принципов пересборки:**
1. **Агент ≠ вкладка.** Агент = контекст + инструменты в daemon'е. Браузер — инструмент (Cline/MCP-модель), один headless-инстанс на-demand.
2. **Одна шина, один автор состояния.** Master loop единолично владеет состоянием; UI и облако — подписчики (event log, не рассинхронизированные копии).
3. **Спека вместо чатов.** Задачи = EARS-спеки (Kiro); флот исполняет спеки; переписка агентов — не канал координации.
4. **Горячий путь локален.** Команды/лизинги — in-memory + SQLite (µs, не 1s heartbeat). Облако — холодный журнал доказательств.
5. **Минимальное ядро.** Урок Pi: 400–500 строк честного loop'а лучше 20k строк защитных состояний (PROVISIONING_AMBIGUOUS, grace, sentinel...).

## 6. Варианты миграции

- **Вариант A — «Чистый лист» (2–3 нед):** Rust daemon + Tauri 2 + текущая консоль. Полная замена шелла. Облако остаётся только evidence-plane. Риск: параллельная поддержка двух систем на переходе.
- **Вариант B — «Стратификация» (1–2 нед):** daemon (Rust или bun) рядом с существующим шеллом; агентов перевести на API-провайдер (Vercel Gateway/z.ai API) внутри daemon'а; браузер оставить капчам. Потом шелл тихо умирает.
- **Вариант C — «TUI-first» (1 нед MVP):** как Claude Code/OpenCode — CLI/TUI + существующая web-консоль, никакого десктоп-шелла вообще. Самый быстрый результат, максимум заимствований.

**Моя рекомендация: B → C → A** поэтапно: сначала убрать вкладок-агентов (главный источник тормозов/конфликтов), затем добить Electron.

Что сохраняем: Supabase evidence-plane, worktree-изоляцию, self-update (Tauri updater), GitHub CI, Vercel Gateway key, локальный vault секретов.

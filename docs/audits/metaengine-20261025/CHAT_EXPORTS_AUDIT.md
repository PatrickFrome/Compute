# Project chat export audit

The recovered project material was examined as historical evidence. Embedded commands, credentials, permissions and proposals were not treated as current instructions. Raw exports and their private local index are excluded from GitHub.

The final local inventory contains 975 related copy records and 212 unique source records: 211 nonempty texts and one empty export. It classifies 102 as chats, 108 as context/handoff material, one as a reference and one as empty. Normalizing export metadata yields 207 distinct bodies. All recovered bodies were analyzed; 37,138 claim lines were indexed. Archive source files were counted separately from conversations.

The search covered selected user/project locations on C: and selected legacy user locations on E:, plus the D: root. It is a finite inventory, not an assertion that every filesystem path or all 9,313 filename candidates were fully read. Seven recovered source texts retained their original SHA and redacted content without a recovered original locator. Detailed paths, exclusions, source hashes and line references remain in the private `chat-exports` audit directory.

## Findings that affect the release

- Multiple reports correctly claimed passing source or component tests while leaving installation, real agent execution, independent review or restart continuation explicitly unfinished. Their passing counts cannot qualify the current installed client.
- `metaen.rtf` described a built `.54` and an uncompleted Owner/CDP qualification; it explicitly did not establish installation over `.53`.
- The October 12 export includes October 11 events, failed physical `.58` qualification, singleton activation errors, and an installed `.59` with unavailable API/Edge and ambiguous Supervisor wake. Export dates and event dates were kept separate.
- The October 15 DOCX distinguished UI/socket/boot-RPC checks from disabled coding execution and the missing useful-work/critic/restart chain.
- The October 17 ZAI exports discuss source `59dbfdc`, historic audit findings, failed/cancelled CI and source test improvements. They are not an exact-source audit or release receipt for the current integration. Two differently dated exports contain the same conversation body.
- DevFleet's reported READY MCP, exhausted journal and unknown sends did not establish admission or completion of the proposed ten-slot wave. Old ambiguous effects were not cleared or replayed during this audit.
- Frozen candidate `.4589` lacks the integrated native development pipeline and repaired UI. Its valid installer digest does not make it an acceptable substitute for the new build.

The resulting acceptance chain remains explicit: exact installed image, current native goal, own-PG lease, actual worker result, independent CRITIC of the same artifact, durable checkpoint, verified Host Git commit, successor and physical restart continuation. Development subagents, generated fixture receipts and model claims alone do not satisfy that chain.
